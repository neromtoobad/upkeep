I replaced the v1-style format tokens with date-fns v4's Unicode tokens: `DD/MM/YYYY` → `dd/MM/yyyy` (lowercase `dd`/`yyyy` for calendar day/year — the uppercase versions are ISO week-numbering tokens that date-fns v4 rejects), and `dddd D MMMM` → `EEEE d MMMM` (weekday is now `EEEE`, day-of-month is lowercase `d` since uppercase `D` now means day-of-year). This matches the console error and keeps the displayed date format identical for users.
